# LocadoraVeiculos2026

Sistema de locadora de veículos. Monorepo: API .NET (`Server/`) + SPA Angular (`client/`). Código e commits em português.

## Arquitetura

### Server (.NET 8, solution `Server/LocadoraVeiculos2026.sln`)
Camadas (pastas ≠ nome dos projetos/namespaces: pastas `LocadoraVeiculos.*`, namespaces `LocadoraDeVeiculos.*`):

| Pasta | Papel |
|---|---|
| `LocadoraVeiculos2026/` | WebApi (Program.cs, Controllers, `Models/` = requests, `Config/` = CORS, Identity/JWT, Swagger, migrations auto) |
| `LocadoraVeiculos.Aplicacao/` | CQRS com MediatR: `Modulo*/Commands`, `Handlers`, `Validators` (FluentValidation), resultados via FluentResults |
| `LocadoraVeiculos.Dominio/` | Entidades (`EntidadeBase`), Identity (`Usuario`, `Cargo`, tokens), `ITenantProvider` |
| `LocadoraVeiculos.Infraestrutura.Orm/` | EF Core 8 + SQL Server: `AppDbContext`, repositórios, mapeadores, `Migrations/` |
| `LocadoraDeVeiculos.Infraestrutura.jwt/` | `AccessTokenProvider`, `RefreshTokenProvider` |

- Módulos existentes: Autenticação, Funcionário, GrupoVeiculos, Condutor (pertence a um cliente que não muda na edição; CPF único por cliente — a mesma pessoa pode ser condutora de clientes diferentes; `ValidadeCnh` é `DateOnly` (JSON yyyy-MM-dd); CNH vencida pode ser cadastrada e vem com `CnhVencida=true`, o aluguel é que exigirá CNH em dia; excluir cliente com condutores → 422), Cliente (**sem cadastro avulso**: não existe `POST api/clientes`; o cliente nasce no `POST api/alugueis` com `NovoCliente` (`ClienteDoAluguelServico`: cria Cliente + Condutor, PF é o próprio condutor e só informa `ValidadeCnh`, PJ informa o `Condutor`; CPF/CNPJ repetido na locadora → 409 "selecione-o na lista"; se o aluguel falhar o cliente/condutor criados são apagados — mesma compensação ao aprovar reserva; `CondutorId` e `NovoCliente` são excludentes, e `NovoCliente` não vale na edição; a simulação `calcular` aceita `NovoCliente` sem validá-lo) ou ao aprovar uma reserva; só a locadora que alugou o vê, pelo filtro de empresa; GET/PUT/DELETE continuam) (uma tabela só: `TipoCliente` PessoaFisica/PessoaJuridica; PF tem CPF/RG/CNH, PJ tem CNPJ; CPF/CNPJ únicos por empresa e validados com dígitos verificadores em `Aplicacao/Compartilhado/DocumentosUtil`; PF pode ter `PessoaJuridicaId`; o tipo não muda na edição; excluir PJ com PF vinculada → 422; os validadores por tipo são `internal` e escolhidos no handler), TaxaServico (catálogo de taxas: nome único por empresa sem diferenciar maiúsculas, preço, `TipoCobrancaTaxa` Fixo|Diario; escrita só `Empresa`), Automovel (placa única por empresa, normalizada sem hífen; foto em `varbinary(max)` no próprio registro, servida só por endpoint autenticado, validada pela assinatura real do arquivo — JPEG/PNG/WebP, máx. 2 MB, SVG recusado; listagem usa projeção `AutomovelResumo` sem os bytes; excluir grupo com automóveis → 422), PlanoCobranca (um plano por grupo com 3 modalidades Diário/Controlado/Livre; índice único filtrado por `Excluido = 0`; excluir grupo com plano → 422), Parceiro (só `Nome`; excluir com cupom → 422), Cupom (`Nome` único por empresa, `Tipo` `TipoDesconto` Valor|Percentual (percentual: 0,01–100, validado em `RegrasDoCupom.ValorDoCupom`), `Valor` em reais ou %, `DataValidade` DateOnly inclusive, `ParceiroId`; escrita só `Empresa`; ranking `GET api/cupons/mais-utilizados` com cupons e parceiros; cadastrar exige validade ≥ hoje, mas editar aceita data passada = encerrar), Configuração (preço dos 4 combustíveis + diária do seguro `Cliente`/`Terceiros`; entidade `Configuracao` única por empresa, upsert; `TipoCombustivel`/`TipoSeguro` em `Dominio/Compartilhado`), Aluguel (ver abaixo). **Cupom no aluguel:** `DadosAluguelDto.CupomId?`; o aluguel copia `CupomId/CupomNome/CupomValor/CupomTipo` (`AluguelDto` expõe `CupomTipo/CupomValor`); desconto = min(valor, consumo) ou, se percentual, consumo × % arredondado — consumo exclui caução, multa e combustível; só cupom não expirado (quem já usa o cupom mantém ao editar), um uso por cliente (`ClienteJaUsouCupomAsync`, ignora o próprio aluguel e os excluídos); cupom em aluguel aberto não exclui. **Aluguel** (`ModuloAluguel`): guarda *snapshot* de nomes, plano, seguro e taxas (`AluguelTaxa`), então mudar preços depois não altera o aluguel. Regras assumidas da especificação: caução fixa R$ 1.000 INCLUÍDA nos totais; dias = max(1, retorno − saída); Diário = diárias + km rodados × preço/km; Controlado = km acima da franquia (kmDisponíveis × dias) × preço extrapolado; Livre = só diárias; seguro por dia (preço em Configurações); taxa Fixo cobra 1× e Diario × dias; devolução com tanque não cheio cobra capacidade × preço do combustível (config); atraso = multa de 10% sobre diárias+km+taxas+seguro; valor final = caução + tudo. Carro ocupado = outro aluguel em aberto sobreposto (vencido e não devolvido ocupa até hoje); CNH precisa valer até o retorno previsto; só edita em aberto, só exclui concluído. Cálculos em `Aluguel.CalcularPrevisto/CalcularFinal` e montagem em `AluguelServico`. Editar troca `Taxas`: novos `AluguelTaxa` têm Id preenchido, então o handler marca `EntityState.Added` (senão o EF faz UPDATE e dá concorrência). Erros `OperacaoBloqueada` → 422 (ex.: editar automóvel/taxa em aluguel aberto). Excluir automóvel/taxa/condutor/cliente/plano/funcionário ligado a aluguel em aberto → 422. **Catálogo / conta de Cliente:** `CargoUsuario.Cliente` não tem claim `EmpresaId` (AccessTokenProvider), então os filtros globais por empresa não devolvem nada para ele e as rotas de gestão dão 403. `RepositorioCatalogoEmOrm` é o único lugar que atravessa as locadoras: usa `IgnoreQueryFilters()` mas respeita `Excluido`, não expõe a placa, calcula a menor diária entre os 3 planos do grupo e a disponibilidade com a mesma regra do aluguel (vencido e não devolvido ocupa até hoje). O nome da locadora é o `FullName` da conta Empresa (não existe campo próprio ainda). Locadora/Funcionário NÃO acessam `api/catalogo`. **Reserva online:** `PerfilCliente` (Meus dados: CPF/RG/CNH/telefone/endereço, 1 por conta; `GET/PUT api/meus-dados`) e `Reserva` (`api/minhas-reservas` do cliente: calcular/criar/listar/cancelar só Pendente, máx. 5 pendentes; `api/reservas` da locadora: listar, `pendentes/total`, aprovar (pede `kmInicial`) e recusar (motivo)). A estimativa usa `Aluguel.CalcularPrevisto` (caução incluída, seguro por dia) **com taxas e cupom**: `DadosReservaDto` tem `TaxasIds` (do catálogo da locadora do carro; `GET api/catalogo/{id}` devolve `taxas`) e `Cupom` (NOME digitado, procurado sem diferenciar maiúsculas na locadora do carro por `RepositorioReservaEmOrm.SelecionarCupomPorNomeAsync`); regras do cupom = as do aluguel (não vencido; um uso por cliente por locadora, conferido por pedido pendente/aprovado com o cupom e por aluguel do mesmo CPF); erros 400 com mensagem ("Não encontramos este cupom", "expirou", "já usou"). `Reserva` guarda cópia: `ValorTaxas`, `ValorDesconto`, `CupomId/Nome/Tipo/Valor` e `Taxas` (`ReservaTaxa`, sem FK para a taxa original). Ao aprovar, o aluguel é montado com os mesmos `TaxasIds` e `CupomId`: se o cupom venceu ou a taxa saiu do catálogo no meio-tempo, a aprovação falha com a mensagem e o pedido continua pendente. Aprovar cria/reaproveita o Cliente PF por CPF + Condutor e monta o Aluguel por `AluguelServico.MontarAsync`; falha se o carro foi alugado nesse meio-tempo. O telefone da locadora (`Configuracao.Telefone`, `NomeFantasia`; `GET/PUT api/configuracoes/locadora`, só `Empresa`) só aparece ao cliente com a reserva Aprovada. `GET api/catalogo/{id}` devolve os planos e só os seguros que a locadora oferece. **Chat** (`ModuloConversa`: `Conversa` por cliente+locadora, índice único filtrado `(EmpresaId, UsuarioClienteId)`, e `Mensagem` até 1000 caracteres; contadores `NaoLidasCliente/NaoLidasLocadora`; filtro global por empresa em `Conversa`, o lado do cliente usa `IgnoreQueryFilters` filtrando por `UsuarioClienteId`): `api/minhas-conversas` (Cliente: listar, iniciar por `automovelId`, abrir (marca lidas), enviar, `nao-lidas/total`) e `api/conversas` (Empresa/Funcionário: caixa de entrada compartilhada). `ConversaServico.RegistrarAsync` grava, conta não lida da outra ponta, avisa em tempo real por `IChatNotificador` (implementado em `Config/Chat/ChatHub.cs` com `IHubContext`; grupos `usuario-{id}` para o cliente e `empresa-{EmpresaId}` para a locadora; evento `MensagemRecebida`) e só manda e-mail quando o contador foi de 0 para 1. Hub em `/hubs/chat` (`[Authorize]`); o WebSocket não leva cabeçalho, então `IdentityConfig` lê `?access_token=` só nas rotas `/hubs`. Limite `LIMITE_MENSAGENS_POR_MINUTO` (padrão 20) POR USUÁRIO (política `mensagens`; por isso `UseRateLimiter` roda depois de `UseAuthentication`). Excluir conta (cliente ou locadora) apaga as conversas e mensagens de verdade (`Include(Mensagens)` porque o provedor em memória dos testes não faz cascata). Nos testes o SignalR usa `Microsoft.AspNetCore.SignalR.Client` com `LongPolling` sobre o `TestServer`. **Segurança:** limites de tentativas por IP (login, cadastro, recuperação → 429, chaves `LIMITE_*`) e chaves de proteção persistentes (`DATA_PROTECTION_PATH`). **Exclusão da própria conta (LGPD)** (`ModuloConta/ContaServico`, `api/conta`): a linha de `Usuario` NUNCA é apagada (todas as tabelas apontam para `EmpresaId` = Usuario da empresa, FK Restrict) — ela é anonimizada: `UserName/Email` viram `excluido-{id}`/`@excluido.invalid`, sem senha, `LockoutEnd=Max`, `AccessTokenVersionId` novo, refresh tokens apagados, `ContaExcluidaEmUtc` preenchido (o e-mail fica livre para novo cadastro). **Cliente** (`POST excluir` {senha, confirmacao=EXCLUIR}, só cargo Cliente): imediata; barra se alguma reserva dele tem aluguel em aberto (422); cancela reservas pendentes; apaga `PerfilCliente`; anonimiza as reservas e os Cliente/Condutor/Aluguel (snapshot de nomes) criados a partir delas ("Conta excluída", CPF vira `ANON-xxxxxxxxx` por causa dos índices únicos). **Locadora/Empresa** (`POST agendar-exclusao` {senha, nomeDaEmpresa}, `POST cancelar-exclusao`, `GET situacao`): agenda `Usuario.ExclusaoAgendadaParaUtc` = hoje + 7 dias (continua entrando e usando o sistema; a tela mostra faixa com a data); barra com aluguel em aberto ou reserva pendente; `ExclusoesAgendadasHostedService` (de hora em hora; desligado com `EXCLUSOES_AGENDADAS_DESLIGADAS=true`, usado nos testes, que chamam `ContaServico.ExecutarAgendadasAsync(agora)`) executa: marca tudo da empresa como `Excluido`, anonimiza clientes/condutores/aluguéis/reservas/funcionários e as contas de login (empresa e funcionários), apaga foto dos carros e telefone/nome fantasia; se surgiu pendência no prazo, adia 1 dia. Funcionário não exclui a própria conta. **Termos de Uso e Privacidade:** o cadastro (`registrar`/`registrar-cliente`) exige `aceitouTermos=true` (senão 400, nada é criado nem enviado) e grava `Usuario.AceiteTermosEmUtc` + `VersaoTermosAceita` = `TermosDeUso.VersaoAtual` (`Dominio/ModuloAutenticacao/TermosDeUso.cs`; a mesma data fica em `client/src/app/legal/legal.constantes.ts` — trocar nos dois ao mudar os textos). Contas anteriores e as de funcionário ficam com o aceite vazio. As páginas públicas `/termos-de-uso` e `/privacidade` (`client/src/app/legal/`) são texto fixo no front, com links no rodapé e no cadastro (checkbox obrigatório). O texto diz que a exclusão da conta hoje é por pedido (contato do rodapé) e que a exclusão no sistema é lógica. **Confirmação de e-mail:** `registrar` e `registrar-cliente` NÃO devolvem token: criam a conta com `EmailConfirmed=false` (o construtor de `Usuario` não marca mais como confirmado), mandam o e-mail com o link `{APP_URL ou host}/auth/confirmar-email?email=&codigo=` (token do Identity em Base64Url, vale 24 h pelo provedor `ConfirmacaoDeEmailTokenProvider`; o de senha continua 1 h) e respondem `{email, mensagem}`. `autenticar` com e-mail sem conta OU senha errada responde igual (400 "Login ou senha incorretos.", e o caso sem conta gasta um hash para o tempo não denunciar), então o login não revela quem tem conta; com a senha certa e e-mail não confirmado → 403 (`EmailNaoConfirmado`). `POST confirmar-email` {email, codigo} → 204 e é idempotente (conta já confirmada → 204); `POST reenviar-confirmacao` {email} responde sempre igual (só envia a quem existe e não confirmou). Funcionário criado pelo administrador nasce confirmado; quem redefine a senha pelo link do e-mail também fica confirmado. Sem `SMTP_HOST` ninguém consegue criar conta (o link só vai para o log). Nos testes: `Cenario.CriarContaEEntrar` registra, lê o link em `EmailsDeTeste.Recebidos(email)`, confirma e entra. **Senhas:** `esqueci-senha` responde sempre igual (não revela quem tem conta; funcionário desativado não recebe) e manda o link `{APP_URL ou host}/auth/redefinir-senha?email=&codigo=` (código = token do Identity em Base64Url, vale 1 h, uso único); `redefinir-senha` revoga refresh tokens e troca `AccessTokenVersionId`; `alterar-senha` mantém a sessão atual. E-mail por `IEnviadorDeEmail`: com `SMTP_HOST` (+ `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM`, `SMTP_SSL`) usa SMTP (NÃO testado contra servidor real); sem ele só grava o link no log. Os tokens do Identity usam as chaves de proteção em memória do processo: reiniciar o app invalida links já enviados. Novo módulo = Dominio entidade → Orm mapeador+repositório (+registrar em `DependencyInjection` do Orm) → Aplicacao commands/handlers/validators → Controller + Models → migration.
- Rotas: `api/auth` (autenticar — aceita `tipo` opcional `Cliente`|`Locadora` e recusa o lado errado só DEPOIS de conferir a senha, esqueci-senha/redefinir-senha/alterar-senha, registrar = conta de locadora/Empresa, registrar-cliente = conta de Cliente, rotacionar, sair), `api/catalogo` (SÓ cargo `Cliente`: GET com filtros `retirada/devolucao/texto/categoria/combustivel/anoMinimo/diariaMaxima/locadoraId/apenasDisponiveis/ordenacao/pagina/tamanhoPagina`, `filtros`, `{id}/foto`), `api/funcionarios` (só `Empresa`; inclui `PATCH {id}/status` para ativar/desativar), `api/funcionarios/meu-perfil` (só `Funcionario`: GET/PUT de nome e CPF próprios; o id vem do token), `api/grupos-veiculos` (`Empresa` e `Funcionario`), `api/configuracoes` (GET `Empresa`+`Funcionario`, PUT só `Empresa`), `api/planos-cobranca` (GET `Empresa`+`Funcionario`; POST/PUT/DELETE só `Empresa`), `api/condutores` (`Empresa`+`Funcionario`; GET aceita `?clienteId=`), `api/clientes` (`Empresa`+`Funcionario`; GET aceita `?tipo=PessoaFisica|PessoaJuridica`), `api/taxas-servicos` (GET `Empresa`+`Funcionario`; POST/PUT/DELETE só `Empresa`), `api/parceiros` e `api/cupons` (GET `Empresa`+`Funcionario`; escrita e ranking só `Empresa`), `api/alugueis` (`Empresa`+`Funcionario`; GET aceita `?status=EmAberto|Concluido`; `POST calcular` simula o preço; `POST {id}/devolucao` e `POST {id}/devolucao/calcular`), `api/automoveis` (`Empresa`+`Funcionario`; GET aceita `?grupoVeiculosId=`; foto em `PUT/GET/DELETE {id}/foto`, upload multipart campo `arquivo`). Desativar um funcionário revoga access/refresh tokens e bloqueia o login.
- Multi-tenant: filtro global `EmpresaId == tenant && !Excluido` em `AppDbContext` (soft delete); tenant vem da claim `EmpresaId` (`IdentityTenantProvider`).
- JWT: token valida `jti` contra `Usuario.AccessTokenVersionId` (revogação); refresh token em cookie (`RefreshTokenCookieService`). Cookie velho/expirado/revogado em `rotacionar` → 401 (erro `NaoAutorizado` em `ResultadosErro`, e o cookie é apagado); `sair` com cookie que não existe mais → 204.
- Em `Development` a API roda `Database.Migrate()` ao subir e expõe Swagger em `/swagger`.

## Configuração local (user-secrets do projeto WebApi, `UserSecretsId` b49f88a1-…)
A API **não sobe** sem estas chaves (lidas via `IConfiguration`): `SQL_CONNECTION_STRING`, `JWT_GENERATION_KEY`, `JWT_AUDIENCE_DOMAIN`, `CORS_ALLOWED_ORIGINS`, `LUCKYPENNY_LICENSE_KEY` (licença do MediatR 14). Hoje todas estão definidas na máquina do dev.
- Banco: LocalDB `(localdb)\mssqllocaldb`, database `LocadoraVeiculos2026DB`, Integrated Security.
- Listar: `dotnet user-secrets list --project Server/LocadoraVeiculos2026` — **não colar a saída em respostas/commits** (contém chave JWT e licença).
- Portas: API `http://localhost:9050` (e `https://localhost:9099` quando o perfil https é usado); front `http://localhost:4200`.

## Comandos (rodar da raiz do repo; shell = PowerShell/Git Bash no Windows)

```bash
# API
dotnet build Server/LocadoraVeiculos2026.sln
dotnet run --project Server/LocadoraVeiculos2026 --launch-profile "https [Dev]"
# Migrations (dotnet-ef global 10.x)
dotnet ef migrations add NomeDaMigration -p Server/LocadoraVeiculos.Infraestrutura.Orm -s Server/LocadoraVeiculos2026
dotnet ef database update -p Server/LocadoraVeiculos.Infraestrutura.Orm -s Server/LocadoraVeiculos2026
# Banco
SqlLocalDB start MSSQLLocalDB
sqlcmd -S "(localdb)\MSSQLLocalDB" -E -d LocadoraVeiculos2026DB -Q "SELECT name FROM sys.tables"
# Front (em client/)
npm install
npm start            # ng serve → :4200
npm run build
npm test             # karma/jasmine (precisa de Chrome)
npx ng ...           # `ng` não está no PATH global
# Testes (Server) — não precisam de SQL Server nem de LocalDB
dotnet test Server/LocadoraVeiculos.Testes
dotnet test Server/LocadoraVeiculos.Testes --collect:"XPlat Code Coverage"   # ~89%, migrations excluídas (coverlet.runsettings)
# Docker (SQL Server + app): copiar .env.example para .env e preencher; abre em http://localhost:8080

```
Projeto de testes `Server/LocadoraVeiculos.Testes` (xUnit): `Dominio/` e `Aplicacao/` = unitários (regras de preço do `Aluguel`, validadores `internal` via `InternalsVisibleTo`, `DocumentosUtil`); `Integracao/` = `ApiFactory` (`WebApplicationFactory<Program>`, ambiente `Testing`, EF InMemory no lugar do SQL Server, chaves de teste fixas) + `Cenario` (empresa com cadastros prontos e geradores de CPF/CNPJ) + `ClienteApi`. Limitação do InMemory: unicidade sem diferenciar maiúsculas depende do collation do SQL Server, então não é testada. CI em `.github/workflows/ci.yml` (build + testes com cobertura + build do Angular). O front ainda não tem testes (`ng test`).
Publicação: a API serve o front Angular (pasta `wwwroot`, ver `Program.cs`: `UseStaticFiles` + `UseRouting` explícito DEPOIS + `MapFallbackToFile` que ignora `/api`), então é uma só origem e o `apiUrl` de produção é `/api`. Em produção as migrations só rodam com `APLICAR_MIGRACOES=true`. `Dockerfile` na raiz gera a imagem única; `.github/workflows/azure.yml` (manual) faz deploy no App Service; guia em `docs/PUBLICAR-AZURE.md`.
